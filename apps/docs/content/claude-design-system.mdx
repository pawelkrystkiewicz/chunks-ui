# Claude design system

Each release of `chunks-ui` comes with a design system for Claude: the theme tokens, every component running live on React 19 with a preview and a guidelines page, the fonts and the logos. Import it into your claude.ai account, and the designs and slides Claude makes with it use the real Chunks UI components and tokens, so what you hand off matches the code.

## Import it

Claude imports the system with its Artifact tool, so use Claude Code or Cowork. A folder dropped on an empty design system page is stored as loose assets, not as a system.

Paste this prompt:

```text
Import the Chunks UI design system into my claude.ai account, or update it if I already have one.

1. Download https://github.com/pawelkrystkiewicz/chunks-ui/releases/latest/download/design-system.tgz into a new, empty folder and extract it there.
2. If I have a design system titled "Chunks UI", read all of its published files back into a new folder, keeping their paths. If I have none, make an empty folder instead.
3. Run `node out/merge.mts --live <that folder>`. It writes merge/ next to out/.
4. If I have no Chunks UI system yet, create one from the Design System type, titled "Chunks UI".
5. Upload the logos that merge/plan.json lists under "uploads" and record them in the system's index, then publish the files in merge/project/. Write the index, design-system.json, last: set its namespace to "ChunksUI" and its `libraries` to the `libraries` in merge/plan.json.
6. Show me merge/report.md, and ask me before you remove anything.
```

`merge.mts` is a copy of [`scripts/design-system/merge.ts`](https://github.com/pawelkrystkiewicz/chunks-ui/blob/master/scripts/design-system/merge.ts). It uses only Node's built-in modules and needs Node 24 or later, or Bun.

`releases/latest` is the newest release. To match the version your app installs, change the link to that release's file, for example `releases/download/chunks-ui@0.5.0/design-system.tgz`. Releases from 0.5.0 on have one. If the link returns 404, the newest release has no tarball yet: take the previous release's `design-system.tgz` from the repo's [Releases page](https://github.com/pawelkrystkiewicz/chunks-ui/releases).

## Update it

Paste the same prompt after a new release. The merge compares each file and token with the release you imported last:

- Changed only in the code: the new release's version.
- Edited only on the page: your edit stays.
- Changed in both: the components' code (bundle, stylesheet, previews, fonts) and the tokens take the new release's version. Guidelines and the brand book keep your edit, and the report lists them so you can compare.
- Nothing is deleted. A component or token that the code no longer has is listed in the report for you to decide on.

One exception: after the first import, a token's usage note, the colour themes, the shadows, the type styles and the font list keep your copy, whatever a release changes. The merge compares only token values and font stacks.

## Use your own theme

The previews read their colours, radius, control height and fonts from the system's tokens. Change `primary` on the design system page, and every button, checkbox and slider in the previews follows.

To bring in a theme from [Create](/create), open **Get code**, copy the theme CSS and ask Claude to set the matching tokens in the system's `tokens.json`. An update keeps a token you changed, unless the release changes that token too.
