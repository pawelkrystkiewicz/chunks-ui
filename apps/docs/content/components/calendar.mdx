# Calendar

A standalone date picker grid built without an external primitive. Supports controlled and uncontrolled selection, min/max bounds, and custom disabled-date predicates.

## Import

```tsx
import { Calendar } from "chunks-ui";
```

## Basic Usage

```tsx
<Calendar />
```

## Controlled

```tsx
function ControlledCalendar() {
  const [date, setDate] = useState<Date | null>(null);

  return (
    <Calendar value={date} onValueChange={setDate} />
  );
}
```

<CalendarControlledExample />

When `value` changes to another day, the calendar shows that day's month. A re-render with the same day, such as an inline `value={new Date()}`, keeps the month the user moved to. The same rule means that setting a new `Date` for the day that is already selected does not move the view back, so a "Today" button does nothing visible while today is selected and the user is on another month. To show the month again, control the month: see [Shown Month](#shown-month).

## Shown Month

The calendar opens on the month of the selected day, else today's, and the arrows and keys move it. To control the shown month, pass `month`, any date in that month, and `onMonthChange`. `onMonthChange` gets the first day of the month the user moves to, at local midnight: by the arrows, by a key that moves focus out of the shown month, or by a click on a day from a neighbouring month. The view then waits for a new `month`. If you keep the month, a key that would leave it leaves focus where it is.

```tsx
function MonthCalendar() {
  const [date, setDate] = useState<Date | null>(null);
  const [month, setMonth] = useState(() => new Date());

  return (
    <>
      <Button
        onClick={() => {
          const today = new Date();
          setDate(today);
          setMonth(today);
        }}
      >
        Today
      </Button>
      <Calendar value={date} onValueChange={setDate} month={month} onMonthChange={setMonth} />
    </>
  );
}
```

With `month`, a new `value` does not move the view: set `month` too, as the Today button does. An Invalid Date, or a date before year 1, as `month` shows the selected day's month, else today's.

Without `month`, `onMonthChange` still tells you when the user moves to another month, for example to load that month's data. A new `value` that moves the view does not call it.

## Disabled Dates

Use `min`/`max` to set a date range, or `isDateDisabled` to disable individual dates with a predicate:

```tsx
const today = new Date();
const isWeekend = (date: Date) => date.getDay() === 0 || date.getDay() === 6;

<Calendar
  min={today}
  isDateDisabled={isWeekend}
/>
```

## Week Start and Outside Days

`weekStartsOn` sets the first column of the week: `0` is Sunday (the default), `1` is Monday. `showOutsideDays` fills the empty cells before the 1st and after the last day of the month with dimmed days from the neighbouring months. Clicking one of them selects it and shows its month. They are never Tab stops. In forced-colors mode, such as a Windows contrast theme, they take the system colour for dimmed text (`GrayText`).

```tsx
<Calendar weekStartsOn={1} showOutsideDays />
```

## Keyboard

The day grid follows the keyboard pattern of the [WAI-ARIA date picker example](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/examples/datepicker-dialog/). It has one Tab stop: the selected day if it is in the shown month, else today, else the 1st of the month. After you move with the keys, the day you moved to becomes the Tab stop. Days from neighbouring months (`showOutsideDays`) are never Tab stops.

| Key | Moves focus to |
| --- | --- |
| <kbd>←</kbd> / <kbd>→</kbd> | The previous / next day |
| <kbd>↑</kbd> / <kbd>↓</kbd> | The same weekday in the previous / next week |
| <kbd>Home</kbd> / <kbd>End</kbd> | The first / last day of the week, following `weekStartsOn` |
| <kbd>Page Up</kbd> / <kbd>Page Down</kbd> | The same day in the previous / next month |
| <kbd>Shift</kbd> + <kbd>Page Up</kbd> / <kbd>Page Down</kbd> | The same day in the previous / next year |

<kbd>Enter</kbd> or <kbd>Space</kbd> selects the focused day. When focus moves past the shown month, the calendar shows the new month. If the target month is shorter, focus goes to its last day: Page Up from March 31 goes to February 28.

Disabled days (`min`, `max`, `isDateDisabled`) can take focus, and screen readers announce them as unavailable. Arrow keys do not skip them, but Enter, Space and clicks do not select them.

The left and right arrows are not mirrored in right-to-left layouts.

## Labels

`labels` replaces the built-in English text, for example to translate it. Keys you leave out keep their default from `DEFAULT_CALENDAR_LABELS`. The keys that depend on a date are functions of that date, so you can pass `Intl` formatters. They get the date at local midnight: format it in the local time zone, not with `timeZone: "UTC"`. A server component can't pass functions, so set them in a client component. See [Labels](/labels).
