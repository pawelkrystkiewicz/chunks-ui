# Label

A standalone form label with consistent typography. Use when you need a label outside of a `Field` context. For labels inside a `Field.Root`, use `Field.Label` instead.

## Import

```tsx
import { Label } from "chunks-ui";
```

## Basic Usage

```tsx
<Label htmlFor="email">Email address</Label>
```

<Container>
  <Label htmlFor="email">Email address</Label>
</Container>

## With Input

```tsx
<div className="flex flex-col gap-1.5">
  <Label htmlFor="username">Username</Label>
  <input id="username" className="border rounded px-3 py-1.5 text-sm" />
</div>
```

<Container>
  <div className="flex flex-col gap-1.5">
    <Label htmlFor="username">Username</Label>
    <input id="username" className="rounded border px-3 py-1.5 text-sm" />
  </div>
</Container>

## Next to a Disabled Control

The label dims (50% opacity, `not-allowed` cursor) when the control right after it, its next sibling, is disabled. It reacts to that sibling, not to the control that `htmlFor` points at. This works for a native `<input>`, `<textarea>` or `<select>`, `Input` without adornments, `Textarea`, and Base UI parts that set `data-disabled`, such as `Checkbox.Root` and `Switch.Root`. Because only the next sibling counts, labels in a flat grid of label and control pairs each follow their own control.

```tsx
<div className="flex items-center gap-2">
  <Label htmlFor="terms">Accept terms</Label>
  <Checkbox.Root id="terms" disabled>
    <Checkbox.Indicator />
  </Checkbox.Root>
</div>
```

<Container>
  <div className="flex items-center gap-2">
    <Label htmlFor="terms">Accept terms</Label>
    <Checkbox.Root id="terms" disabled>
      <Checkbox.Indicator />
    </Checkbox.Root>
  </div>
</Container>

The label doesn't dim in other layouts: when the control comes first (a native input with the `peer` class is the one exception), when something else sits between the label and the control, when the label wraps the control, or when the two have different parents. An `Input` with adornments is one such case, because the label's next sibling is then the wrapper around the input. In these layouts, put each label and control pair in its own wrapper in the label-first order, or dim the label yourself, for example with `className={cn(disabled && "opacity-50")}`. Inside a `Field.Root`, use `Field.Label`, which dims when the field is disabled.

## Props

This component accepts all props from the native `<label>` element.

## Styling

- `font-medium text-sm leading-none` — matches `Field.Label` typography
- `has-[+:disabled]:` and `has-[+[data-disabled]]:` set `opacity-50` and `cursor-not-allowed` when the control right after the label is disabled (see [Next to a Disabled Control](#next-to-a-disabled-control))
- `peer-disabled:cursor-not-allowed peer-disabled:opacity-50` — dims after a disabled native input with the `peer` class
