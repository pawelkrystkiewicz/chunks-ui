# Input

A styled text input built on Base UI's `Input` primitive. Supports start/end adornments, a clear button, and error states via `data-[invalid]`.

## Import

```tsx
import { Input } from 'chunks-ui'
```

## Basic Usage

```tsx
<Input placeholder="Enter your name" aria-label="Name" />
```

<Container>
  <Input placeholder="Enter your name" aria-label="Name" />
</Container>

## Adornments

Use `startAdornment` and `endAdornment` to place icons or text at the edges of the input:

```tsx
<Input startAdornment={<SearchIcon className="size-4" />} placeholder="Search..." aria-label="Search" />
```

<Container>
  <Input startAdornment={<SearchIcon className="size-4" />} placeholder="Search..." aria-label="Search" />
</Container>

```tsx
<Input endAdornment={<span className="text-xs text-muted-foreground">USD</span>} placeholder="0.00" aria-label="Amount" />
```

<Container>
  <Input endAdornment={<span className="text-xs text-muted-foreground">USD</span>} placeholder="0.00" aria-label="Amount" />
</Container>

## Clear Button

Add `clearable` to show a built-in clear button (the `ClearButton` component). The button shows while the input has text, and not on a `disabled` or `readOnly` input. While it is visible it takes the place of `endAdornment`, so the two don't show together.

Clearing empties the input the way typing does: `onChange` and `onValueChange` fire with `''`. Focus stays in the input, because a click on the button doesn't blur it, so a `Field.Root` with `validationMode="onBlur"` doesn't validate in the middle of a clear.

```tsx
<Input defaultValue="Hello" clearable placeholder="Search..." aria-label="Search" />
```

<Container>
  <Input defaultValue="Hello" clearable placeholder="Search..." aria-label="Search" />
</Container>

A controlled input is cleared by the handler that sets its `value`:

```tsx
export const ClearableSearch = () => {
  const [value, setValue] = useState('')

  return (
    <Input value={value} onValueChange={setValue} clearable placeholder="Search..." aria-label="Search" />
  )
}
```

### onClear

`onClear` is called after the button clears the input. Passing it also shows the button, without `clearable`. With `onClear`, a controlled input fires no `onChange` or `onValueChange`, and keeps its `value` until your `onClear` sets it to `''`:

```tsx
export const InputWithClearButton = () => {
  const [value, setValue] = useState('')

  return (
    <Input
      value={value}
      onChange={e => setValue(e.target.value)}
      onClear={() => setValue('')}
      placeholder="Search..."
      aria-label="Search"
    />
  )
}
```

<Container>
  <InputWithClearButton />
</Container>

An uncontrolled input (`defaultValue`) is emptied for you, as with `clearable`, and `onClear` only tells you that it happened.

## Error State

The input styles change when the `data-invalid` attribute is present (set automatically by `Field.Root` with `invalid` prop, or manually). `Field.Error` shows only when the field fails validation, so add `match` to show it whenever you set `invalid` yourself. `match={true}` shows the error regardless of `invalid`, so pass `match={hasError}` (or render `Field.Error` only while the field is invalid). This example is always invalid, so `match` can stay:

```tsx
<Field.Root invalid>
  <Field.Label>Email</Field.Label>
  <Input placeholder="user@example.com" />
  <Field.Error match>Invalid email address</Field.Error>
</Field.Root>
```

## With Field

Wrap `Input` in a `Field` for labels, descriptions, and validation:

```tsx
<Field.Root>
  <Field.Label>Username</Field.Label>
  <Field.Description>Choose a unique username</Field.Description>
  <Input placeholder="johndoe" />
</Field.Root>
```
