Fixed: in a trigger-style `Combobox` (a button as the trigger, the search input in the popup), a `Combobox.Value` wider than its trigger stays on one line and ends in an ellipsis before the chevron. Before, a long word ran past the trigger's edge and pushed the chevron out of it, and a value of several words wrapped onto lines above and below the trigger. Base UI's `Combobox.Value` renders no element, so nothing could clip it; it now renders a `<span>` with the clip, as `Select.Value` does. `whitespace-normal` in its `className` brings back wrapping, and other span props reach the span. The `<span>` fills the trigger's free space (`flex-1`), so an element beside it, such as a badge, keeps its width on one line and the value truncates first; `flex-initial` in its `className` sizes it by its text. A function child in a multi-select is the one case left without the `<span>`, whatever it returns, so a multi-select that returns its chips from `Combobox.Value` keeps its layout. `className` and the span's props are dropped there, and text it returns is not clipped: return your own clipped element, such as `<span className="flex-1 truncate text-start">...</span>`. The props type of `Combobox.Value` is exported as `ComboboxValueProps`. `Combobox.Trigger` now has `min-w-0 max-w-full`, so the one-line value does not widen it past its container: it shrinks beside other items in a flex row, and a trigger sized by its value (`w-auto`) stops at the container's width. The default chevron over an input is unchanged.
