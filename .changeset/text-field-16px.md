Fixed: on iOS, Safari zoomed the page when `Input`, `Textarea`, `NumberField.Input` or `Combobox.Input` took focus, because their text was 14px and iOS zooms into a field with text under 16px. Their text is now 16px below the `md` breakpoint (768px by default, `max-md:text-base`) and 14px from `md` up, as before; `InputCopy`, which renders an `Input`, and your own elements through `inputVariants()` follow. Below `md` a `Textarea` row is 4px taller (24px), and a field that takes its width from its content, such as a `NumberField` in a flex row, is about 20px wider, because an input's default width follows its font size: give it a width to keep the old one. A text-size class you pass, such as `text-lg`, still applies from `md` up; below `md` the field stays 16px, so pass a `max-md:` class, such as `max-md:text-lg`, to change it there. A size under 16px there brings the zoom back. On an `Input` with adornments (`startAdornment`, `endAdornment`, `clearable` or `onClear`) and in `InputCopy`, a string `className` goes on the wrapper, so a text-size class there does not change the field: pass a function, `className={() => "max-md:text-lg"}`, which reaches the input. A phone held sideways can be wider than `md`, where the field is 14px and Safari zooms again; `pointer-coarse:text-base` (Tailwind 4.1 or newer) keeps 16px on touch screens, and the 16px assumes the default root font size, because `text-base` is 1rem.
